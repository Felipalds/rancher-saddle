# CLI Reference

`saddle` is the compiled binary. Running it with no arguments launches the fullscreen TUI. Every operation available in the TUI is also reachable as a subcommand.

## Global flags

| Flag | Default | Description |
|---|---|---|
| `--config <path>` | `config.yaml` | Path to clusters configuration file — respected by `list`, `create`, `delete`, and `upgrade` |

---

## Clusters

### `saddle list`

List all clusters from `config.yaml`.

```
saddle list
```

Output columns: NAME, STATUS, NODES, REGION, CREATED, RANCHER URL

---

### `saddle create [cluster-name]`

Create a new cluster. Without infrastructure flags the TUI form opens. When `--subnet` or `--credential` is provided, all deployment happens non-interactively.

```
saddle create my-cluster \
  --credential prod \
  --subnet subnet-0abc12345 \
  --security-group sg-0abc12345 \
  --ssh-key-name my-key \
  --ssh-key-path ~/.ssh/my-key.pem
```

**Flags**

| Flag | Default | Description |
|---|---|---|
| `--name`, `-n` | | Cluster name (also accepted as positional argument) |
| `--method` | `local` | Installation method: `local` or `docker` |
| `--provider` | `aws` | Cloud provider (`aws`) |
| `--credential` | | Credential name from `cloud-credentials.yaml` **(required for non-interactive)** |
| `--distro` | `rke2` | Kubernetes distribution: `rke2` or `k3s` (ignored in docker mode) |
| `--k8s-version` | auto | Kubernetes version, e.g. `v1.33.7+rke2r1` |
| `--node-prefix` | `k8s-node` | EC2 instance name prefix |
| `--region` | `us-east-1` | AWS region |
| `--subnet` | | AWS subnet ID **(required for non-interactive)** |
| `--security-group` | | AWS security group ID **(required for non-interactive)** |
| `--os-image` | `Ubuntu 22.04 LTS` | Distro name looked up in `amis.yaml` |
| `--ami` | | AMI ID — overrides `--os-image` |
| `--instance-type` | `t3.xlarge` | EC2 instance type |
| `--instance-count` | `3` | Number of nodes (forced to `1` in docker mode) |
| `--ssh-key-name` | | AWS KeyPair name **(required for non-interactive)** |
| `--ssh-key-path` | | Local path to SSH private key **(required for non-interactive)** |
| `--ssh-user` | `ubuntu` | SSH login user |
| `--deploy-rancher` | `false` | Deploy Rancher on the cluster |
| `--rancher-prime` | `false` | Use Rancher Prime (`registry.suse.com`) |
| `--rancher-version` | `2.11.7` | Rancher version |
| `--bootstrap-password` | `admin` | Rancher bootstrap password |
| `--image-tag` | | Hotfix image tag override, e.g. `v0.0.0-hotfix-abc.1` |
| `--debug` | `false` | Enable Rancher debug mode |
| `--host-port` | `443` | HTTPS port (docker mode only) |
| `--profile` | | Load a saved profile to pre-fill infra settings (explicit flags override profile values) |

**Docker mode example**

```
saddle create rancher-dev \
  --method docker \
  --credential prod \
  --subnet subnet-0abc12345 \
  --security-group sg-0abc12345 \
  --ssh-key-name my-key \
  --ssh-key-path ~/.ssh/my-key.pem \
  --rancher-version 2.11.7
```

**Using a profile**

```
saddle create staging \
  --profile us-east \
  --credential prod \
  --deploy-rancher
```

### `saddle apply -f <file.yaml>`

Provision one or more clusters from a YAML blueprint file. The file schema is identical to `config.yaml` — it can be hand-written or generated by an LLM:

```
saddle apply -f blueprint.yaml
saddle apply -f blueprint.yaml --credential prod
saddle apply -f blueprint.yaml repro-sure-11610   # apply only one cluster from the file
```

The command reads every cluster defined in the file and calls the full deployment workflow for each one. If cluster names are passed as arguments, only those clusters are applied.

**Blueprint YAML schema** (generated by LLM or hand-written):

```yaml
clusters:
  repro-sure-11610:
    provider:
      type: aws
      config:
        access_key: PLACEHOLDER_ACCESS_KEY
        secret_key: PLACEHOLDER_SECRET_KEY
        region: us-west-2
        ami: ami-0a3e3ef8596692376
        instance_type: t3.xlarge
        security_group_id: sg-0abc12345
        subnet_id: subnet-0abc12345
    kubernetes:
      distribution: rke2
      config:
        version: v1.33.7+rke2r1
        deploy_rancher: true
        rancher_version: 2.13.5
        rancher_bootstrap_password: admin
        rancher_prime: false
        rancher_debug: false
    rancher:
      version: 2.13.5
      deploy: true
      prime: false
      bootstrap_password: admin
    ssh:
      key_name: my-key
      private_key_path: ~/.ssh/my-key.pem
      user: ubuntu
    cluster:
      node_prefix: sure-11610
      instance_count: 3
```

**Credential override** — the blueprint may contain placeholder credentials. Use `--credential` to substitute a real credential from `cloud-credentials.yaml`:

```
saddle apply -f blueprint.yaml --credential prod
```

| Flag | Default | Description |
|---|---|---|
| `-f`, `--file` | | Path to clusters YAML blueprint **(required)** |
| `--credential` | | Name of a saved credential to override `access_key` / `secret_key` in the file |
| `--credentials-file` | `cloud-credentials.yaml` | Credentials file to read `--credential` from |
| `--config` | `config.yaml` | Where to track cluster state (global flag) |

### `saddle delete <cluster-name>`

Destroy a cluster's AWS infrastructure and remove it from `config.yaml`.

```
saddle delete my-cluster
saddle delete my-cluster --force
```

| Flag | Default | Description |
|---|---|---|
| `--force`, `-f` | `false` | Skip the `(yes/no)` confirmation |

### `saddle upgrade <cluster-name>`

Upgrade Rancher on an existing cluster. Defaults for unset flags are read from the current cluster configuration.

```
saddle upgrade my-cluster --version 2.11.7
saddle upgrade my-cluster --version 2.11.7 --replicas 2 --audit-log --audit-log-level 2
```

Behavior:
- **K8s clusters** (rke2 / k3s): runs the Ansible upgrade playbook via `internal/upgrade.Runner`.
- **Docker clusters**: SSHs into the host and runs `docker stop && docker rm && docker run` with the new image.
- Progress is streamed to stdout and written to `logs/<cluster-name>-upgrade.log`.
- `config.yaml` is updated: `status` → `upgrading` before, then `running` or `upgrade-failed` after.

| Flag | Default | Description |
|---|---|---|
| `--version` | current | Target Rancher version |
| `--replicas` | `1` | Kubernetes deployment replicas (K8s clusters only) |
| `--audit-log` | `false` | Enable Rancher audit log |
| `--audit-log-level` | `1` | Audit log verbosity (0–3) |
| `--image-tag` | current | Hotfix image tag override |
| `--debug` | `false` | Enable Rancher debug mode |

## Credentials

Manage `cloud-credentials.yaml`. Access keys are masked in list output (`XXXX****XXXX`).

All `credentials` subcommands share a `--credentials-file` flag (default: `cloud-credentials.yaml`) to target an alternative file:

```
saddle credentials --credentials-file /path/to/other-creds.yaml list
```

### `saddle credentials list`

```
saddle credentials list
saddle credentials list --credentials-file staging-creds.yaml
```

### `saddle credentials add`

Add or update an AWS credential. If a credential with the same `--name` already exists it is replaced in full.

```
saddle credentials add \
  --name prod \
  --access-key AKIAIOSFODNN7EXAMPLE \
  --secret-key wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY \
  --region us-east-1
```

| Flag | Required | Description |
|---|---|---|
| `--name` | yes | Credential identifier |
| `--access-key` | yes | AWS access key ID |
| `--secret-key` | yes | AWS secret access key |
| `--region` | | Default AWS region |

### `saddle credentials delete <name>`

```
saddle credentials delete prod
saddle credentials delete prod --force
```

| Flag | Default | Description |
|---|---|---|
| `--force`, `-f` | `false` | Skip the `(yes/no)` confirmation |

### `saddle credentials edit <name>`

Update one or more fields of an existing credential. At least one flag must be provided; only the flags you supply are changed.

```
saddle credentials edit prod --region eu-west-1
saddle credentials edit prod --access-key NEWKEY --secret-key NEWSECRET
```

| Flag | Description |
|---|---|
| `--access-key` | New access key ID |
| `--secret-key` | New secret access key |
| `--region` | New default AWS region |

Providing none of the above flags is an error:

```
$ saddle credentials edit prod
Error: nothing to update: provide at least one of --access-key, --secret-key, --region
```

## Profiles

Manage `profiles.yaml`. Profiles store reusable AWS infrastructure settings that can be loaded into the create form (TUI: `ctrl+p`, CLI: `--profile`).

All `profiles` subcommands share a `--profiles-file` flag (default: `profiles.yaml`):

```
saddle profiles --profiles-file /path/to/other-profiles.yaml list
```

### `saddle profiles list`

```
saddle profiles list
saddle profiles list --profiles-file staging-profiles.yaml
```

### `saddle profiles add`

Create or replace a profile. `--name` is required; all other flags are optional.

```
saddle profiles add \
  --name us-east \
  --region us-east-1 \
  --subnet subnet-0abc12345 \
  --security-group sg-0abc12345 \
  --ami ami-0c7217cdde317cfec \
  --instance-type t3.xlarge \
  --ssh-key-name my-key \
  --ssh-key-path ~/.ssh/my-key.pem \
  --ssh-user ubuntu
```

| Flag | Required | Description |
|---|---|---|
| `--name` | yes | Profile identifier |
| `--region` | | AWS region |
| `--subnet` | | Subnet ID |
| `--security-group` | | Security group ID |
| `--ami` | | AMI ID |
| `--instance-type` | | EC2 instance type |
| `--ssh-key-name` | | AWS KeyPair name |
| `--ssh-key-path` | | Local path to SSH private key |
| `--ssh-user` | | SSH login user |

### `saddle profiles delete <name>`

```
saddle profiles delete us-east
saddle profiles delete us-east --force
```

| Flag | Default | Description |
|---|---|---|
| `--force`, `-f` | `false` | Skip confirmation |

### `saddle profiles edit <name>`

Update specific fields of an existing profile. Only provided flags are changed.

```
saddle profiles edit us-east --instance-type m5.xlarge
saddle profiles edit us-east --region us-east-2 --subnet subnet-new
```

| Flag | Description |
|---|---|
| `--region` | New AWS region |
| `--subnet` | New subnet ID |
| `--security-group` | New security group ID |
| `--ami` | New AMI ID |
| `--instance-type` | New EC2 instance type |
| `--ssh-key-name` | New AWS KeyPair name |
| `--ssh-key-path` | New SSH private key path |
| `--ssh-user` | New SSH login user |

## AMI Catalog

Manage `amis.yaml`. The catalog maps distro names (e.g. `Ubuntu 22.04 LTS`) to AMI IDs per region. The TUI uses this table to resolve the OS Image dropdown. The CLI `create` command uses it when `--os-image` is given without `--ami`.

All `amis` subcommands share a `--amis-file` flag (default: `amis.yaml`):

```
saddle amis --amis-file /path/to/other-amis.yaml list
```

### `saddle amis list`

```
saddle amis list
saddle amis list --amis-file staging-amis.yaml
```

### `saddle amis add`

Add or replace an entry. The composite key is `(--distro, --region)`.

```
saddle amis add \
  --distro "Ubuntu 22.04 LTS" \
  --region us-east-1 \
  --ami ami-0c7217cdde317cfec
```

| Flag | Required | Description |
|---|---|---|
| `--distro` | yes | Distro display name |
| `--region` | yes | AWS region |
| `--ami` | yes | AMI ID |

### `saddle amis delete`

```
saddle amis delete --distro "Ubuntu 22.04 LTS" --region us-east-1
saddle amis delete --distro "Ubuntu 22.04 LTS" --region us-east-1 --force
```

| Flag | Required | Description |
|---|---|---|
| `--distro` | yes | Distro name |
| `--region` | yes | AWS region |
| `--force`, `-f` | | Skip confirmation |

### `saddle amis edit`

Update the AMI ID for an existing `(distro, region)` pair.

```
saddle amis edit \
  --distro "Ubuntu 22.04 LTS" \
  --region us-east-1 \
  --ami ami-0newamiid1234
```

| Flag | Required | Description |
|---|---|---|
| `--distro` | yes | Distro name |
| `--region` | yes | AWS region |
| `--ami` | yes | New AMI ID |

## Log files

All long-running operations write timestamped logs:

| Operation | Log file |
|---|---|
| `create` | `logs/<cluster-name>.log` |
| `upgrade` | `logs/<cluster-name>-upgrade.log` |
| `delete` | stdout (tofu output is streamed directly) |
